# 提交格式要求

## Commit Message

使用以下格式：

```text
<type>(<course>): <summary>
```

常用 type：

- `add`：新增资料。
- `fix`：修正资料、修正命名、替换错误文件。
- `docs`：更新 README、贡献指南、命名规范。
- `chore`：整理目录、更新 manifest、清理重复文件。

示例：

```text
add(离散数学): 补充软件学院23级真题
fix(高等数学A二): 规范课件编号命名
docs(repo): 补充社区共建提交规范
chore(Web编程基础): 更新公开资料清单
```

## PR 标题

PR 标题沿用 commit 格式。一个 PR 尽量只处理一门课或一种文档维护任务。

示例：

```text
add(大学物理): 补充2024练习题与电磁学课件
```

## PR 描述

PR 描述至少包含：

- 课程名。
- 资料类型。
- 年份或适用范围。
- 来源说明：例如老师公开课件、同学回忆版、课程群资料、个人整理。
- 是否需要复核：例如 OCR 不清晰、答案待校对、年份不确定。

可使用模板，模板来源：[jry21223/final-review-template-kit](https://github.com/jry21223/final-review-template-kit)：

```md
## 资料说明

- 课程：
- 类型：
- 年份/范围：
- 来源：

## 检查

- [ ] 文件名符合命名规范
- [ ] 没有个人隐私或账号信息
- [ ] 没有重复提交已有资料
- [ ] 需要复核的问题已说明
```

## 不要混在一个提交里

- 不要把多门课的大量文件和 README 修改混在一个 commit。
- 不要把资料更新和无关格式化、系统文件、临时文件混在一起。
- 不要提交 `.DS_Store`、`__MACOSX`、`._*`、下载临时文件。
